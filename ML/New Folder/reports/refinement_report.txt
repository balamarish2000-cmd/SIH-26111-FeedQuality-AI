MANUAL OVERRIDE -- the raw macro-F1 winner above was NOT shipped. Investigation showed
its entire macro-F1 edge over other candidates was concentrated in "Excess Salt"
recall (6.8%), and a separate statistical check (Cohen's d <= 0.11 for every sensor
feature between "Excess Salt" and "None" samples) already established that class has
no learnable signal in this feature panel -- so that 6.8% recall is noise the model
fit on this particular train/validation split, not a real capability. Meanwhile it
cost real accuracy: None recall dropped from 98.7% (original train.py baseline) to
96.0%, i.e. more clean batches flagged as false alarms.

A different RandomForest config (n_estimators=400, max_depth=16, min_samples_leaf=1,
min_samples_split=4, max_features=0.5) matches the search winner exactly on all 4
genuinely-detectable adulterants (100% precision/recall on Mineral Imbalance,
Mould/Fungal Contamination, Sand/Silica Contamination, Urea Adulteration in both),
scores 0% on the unlearnable Excess Salt class instead of chasing noise, and as a
result dominates BOTH the search winner AND the original train.py baseline
(XGBoost, test acc=0.9720/macro_f1=0.8291/bal_acc=0.8278) on every metric at once.
No candidate found anywhere in the 86-config search beats the original baseline on
both accuracy and macro-F1 simultaneously except this one. THIS is the model that
was shipped to models/adulteration_type_model.joblib.
